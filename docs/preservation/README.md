# Preservation baseline

This directory is the machine-readable safety net for Phase 0 and every later replacement/migration.

`manifest.json` is generated by `npm run manifest` from the current repository. It is intentionally deterministic: timestamps and commit SHAs are not embedded because that would make a clean-tree `manifest:check` fail on every run.

The manifest inventories:

- page routes, route-group-normalised URLs, public/protected status, role gates and dynamic-route status;
- API routes and exported HTTP methods;
- Prisma models, fields, indexes/uniques/ids, enums and SQL RLS policies discoverable from migrations;
- Inngest functions and whether each is registered by the serve handler;
- Vercel cron jobs;
- feature flags and defaults;
- interview state-machine transitions.

## Commands

```bash
npm run manifest
npm run manifest:check
npm run route:matrix -- http://localhost:3000
npm run test:e2e:golden
```

`manifest:check` regenerates the file and fails when the generated result differs from the committed baseline. Any intentional route/API/schema/job/flag/state-machine change therefore appears as a normal PR diff and must be reviewed.

## Review policy

A manifest diff is not automatically a regression. Reviewers must classify every removed or changed item as one of:

1. intentional additive/replacement work with parity evidence and rollback;
2. an expected generated change with no externally observable regression; or
3. an accidental regression that blocks merge.

No legacy route, schema, worker or contract should be removed in the same release that introduces its replacement.

## Route matrix

`scripts/route-matrix.sh` verifies logged-out behavior for static routes. Public routes must return 200. Role-gated routes must redirect to `/auth/signin`. Dynamic routes are skipped unless a fixture value is provided because inventing IDs would turn the gate into noise.

Optional fixtures can be supplied through `ROUTE_MATRIX_FIXTURES` as JSON, keyed by route pattern, for example:

```bash
ROUTE_MATRIX_FIXTURES='{ "/jobs/[id]": "/jobs/seed-job-1" }' npm run route:matrix -- http://localhost:3000
```

## Visual baselines

The golden Playwright suite contains logged-out route-access tests immediately. Authenticated recruiter/candidate visual baselines require deterministic seeded accounts/storage-state and must never be faked with a production-capable auth bypass. The suite accepts `E2E_RECRUITER_STORAGE_STATE` and `E2E_CANDIDATE_STORAGE_STATE` paths when those fixtures are available; until then authenticated screenshot cases are explicitly skipped rather than silently passing.
